## 已修复的重点问题

| 问题 | 修正 | 证据 |
|---|---|---|
| 静止来源重配后无后续取样帧，停在FRAME_PENDING | 首次注册/输入配置变化补一次traversal；连续帧复用状态 | 融合半径0→64的窗口像素与静止页回归 |
| 受限来源首次状态不准确，依赖换代可能绕过旧拓扑检查 | 绑定时读取可用性；来源和依赖epoch变化重检图、作废输入与旧结果 | 禁止来源零捕获、恢复、依赖换代成环被拒绝 |
| JSON已知子对象/数组类型错误静默回落默认，异常嵌套进入平台递归解析 | 严格类型和schema；平台解析前16384字符/16层/单根对象限制 | JVM输入门禁及Android完整参数往返/错误类型/深层拒绝 |
| 调节融合/阴影外扩后实体偏移，Gaussian阴影被留白截断 | 重放同一动效几何到新原点；按启用阶段计算k/4及3.5σ尾部留白 | 留白纯策略JVM与静态选中中心的实际窗口像素 |
| 融合装饰关闭覆盖宿主后设的几何监听 | 转发原监听；关闭只恢复仍持有的监听/背景 | 连续改选、稳定终态、后设监听和背景保持 |
| 关闭融合未清自定义实体，旧纯GPU示例误入位图路径 | clearCustomShapes恢复隐式View几何及旧节点计划 | strict GPU-only渐隐重新产生窗口像素 |
| 自适应质量重新配置不从指定模式开始 | 配置变更重置模式和驻留；重放时间回退重置驻留起点 | 指定等级、阈值、滞回、驻留JVM |
| 来源移除后的迟到完成计数丢失 | 一次转移到会话累计，迟到计数更新累计，不持有来源View | 迟到完成、过期和耗时累计JVM |
| 绘制预算、采样外扩和诊断矩形不一致 | 同时执行会话/表面预算；位移硬限与外扩一致；返回真实录制/物化范围 | 外部红色标记A/B、五范围坐标空间、释放后活跃字节归零 |
| 基准计数累计且零帧仍可成功 | 改为测量区间增量，要求非零FrameMetrics；保留原始数组 | 配对基准实际输出 |
| 混合间隔测试把15次名义20ms当成固定300ms | 按真实采样间隔检查，要求最后一次变化被补采、静止停止 | 完整30项回归，无取消原有间隔约束 |
| 三分支RenderEffect渐进原型触发模拟器退出 | 移除未验证原型，使用固定位图输入的直接Shader计划 | 直接绘制各像素契约通过 |

## 性能与平台边界

同协议下保留多个原始测量。host后端首次配对P95约18.63/18.78ms；完整验收末次配对约54.08/51.64ms（旧/渐进）。
后者分别161/180个FrameMetrics样本；测量期间都录制内容90次，旧代理148次、新代理0次，效果链和Shader构造增量均0；新活跃软件缓冲375840字节。
差异和环境波动明显，不能据此宣称新路径更快、达到某手机帧率或电量验收。数据描述整个窗口帧，非纯Shader GPU耗时。

Windows swiftshader后端在普通页面阶段曾多次使qemu宿主进程发生0xc0000005访问冲突；host后端完整测试通过。
不将软件后端失败改成skip，不取消新像素检查；Linux云端图形栈仍须独立验证。失败日志保留供定位。

新增直接路径是有界软件来源/滤波加GPU材质绘制；低版本和SOFTWARE保留轮廓/固定模糊，不声称实现同样的融合/位移/光照。
颜色支持组为sRGB SDR ARGB8888；扩展色域/HDR为不支持组，拒绝伪称HDR的参数契约，不保留HDR亮度。
来源授权/受保护或独立Surface状态由宿主显式声明；没有跨应用截图、隐藏API或传感器。
固定JSON是参数预设，实时触点/几何/来源事件仍由宿主提供；seed作为复现元数据，当前效果没有随机生成阶段。
