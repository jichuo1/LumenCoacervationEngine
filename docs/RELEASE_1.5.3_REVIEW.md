# 1.5.3 输入框与展开条目交互发布审阅

本次基于 1.5.2 主线 `e84c3f3`，修复长文本输入框的前景描边坐标与长按形变的反向裁剪补偿，并补齐普通当前页的局部外溢。公开 API、契约版本 1、持久化协议与 minSdk 27 保持兼容。发布提交、完整云端结果及所有附件摘要由 Release 的 `VERIFICATION_1.5.3.json` 绑定。

## 分区一：输入框与控件绘制

原生 View 对背景补偿自身的内容滚动，前景描边则在内容画布上绘制；长文本引起的 `scrollX/scrollY` 因而带偏边框。`controlOutline()` 现在返回轻量的前景包装：经有界 Drawable 回调链定位实际前景所属 View，只对这条前景路径补偿有符号的滚动坐标，作为背景或独立绘制时保留原坐标。

包装沿用平台 `DrawableWrapper` 转发状态、边界、层级、着色和失效回调，不改变原描边的颜色、半径、粗细或聚焦/按压规则。文本、光标、选区与内边距仍由输入框管理；包装不存 View/Context 字段，不加滚动监听、轮询、位图抓取或额外图层。零滚动走原绘制路径。

## 分区二：形变几何与当前页外溢

原裁剪适配先保留缩放，再把位移钳制到可容纳该缩放的区间。下沿余量为零而控件放大时，区间可能完全落在负方向，向下拖动因此变为向上补偿。现在只在钳制将反转方向或让零输入漂移时收敛额外缩放，之后继续在真实硬边界内求位移；空间充足路径及按压收缩保持原响应。

已有 `ElasticOverflowPortal` 增加一种有界承载路径：`LumenPagePager` 静止当前页的直接 `LiquidStretchViewport` 子层。补画只携带本次形变单位原先可见的部分，保留其他行、原生裁剪、当前页/窗口边界及可读轮廓。未知视口、活动回弹、不可表达的局部圆角裁剪、特殊硬件内容和原有树规模限制继续保守回退。

当前页外溢仅在 held drag 已捕获后挂载。页切换、运动或来源几何失效由仅在占用期注册的 pre-draw 检查结束；detach 时撤销监听，迟到失败回调仍校验 portal 身份。没有引入每帧位图、布局或控件树遍历。

`ElasticInteractionController`、`ElasticGestureGate` 所在策略文件、`LumenPagePager`、`LumenPageScrollView`、`LiquidStretchViewport` 与 `ElasticGestureClaim` 的原有输入归属实现保持不变。普通滑动先越过 slop 即永久交还原事件流，只有长按捕获后才发送一次原生 CANCEL；1.5.1 顶层回弹视口不在 DOWN 阶段提前禁止横向切页的修复保留。

## 分区三：回归与发行

新增几何性质检查覆盖反向位移、零输入漂移、边缘与裁剪后的非居中 pivot，同时保留原有包含性、按压收缩与有空间时的精确响应。真实窗口用例覆盖长单行/多行文本、正负滚动、RTL 和嵌套前景；展开分节通过真实 Window、分页器、回弹视口和滚动容器分发输入，检查四向拖动、隐藏内容、双向切页、纵向滚动及切页释放。新增五项设备用例在四系统 smoke 中均为必测。

本地完整任务图通过 Debug、全部 JVM 与 Sample release 单测、十模块 Lint、Sample R8、九模块 AAR/sources 及本地 Maven。1,023 项 JVM/源码契约测试零失败、零错误、零跳过；Lint HTML 生效口径为零错误、71 warnings。Python 门禁 51 项通过，修改的发布工作流通过 actionlint。九模块身份、源码包与当前生产源码逐字节一致，七组分发声明完整；Debug APK 的 minSdk 27 平台类型审计人工分类通过，新增包装只使用 minSdk 已存在的平台类型。

输入框回归先在未修改的 1.5.2 实现上于 PMA110/API 37 运行，横向与纵向两项均稳定暴露描边像素移动。物理设备随后断开；修复验证使用独立 applicationId 的本地 API 34 窗口，不替换原有模块或宿主。

首轮 API 34 窗口检查发现嵌套前景测试复用已挂载 Drawable 时被 `View.setForeground` 清空了新回调；夹具改为先解除旧前景再包装，并增加回调归属断言，原像素断言保留。SwiftShader 联合检查在既有生产 Sample 页面用例中发生 Windows headless QEMU 访问冲突退出，事件记录为 `0xc0000005`；严格协议将其判为不完整。切换本地 host GPU/skiagl 后的首次检查又发现重启后的虚拟设备处于锁屏，窗口未布局/未获焦；该失败同样保留。随后明确唤醒、解锁并核对专用 AVD 状态，新增窗口夹具也在原五秒时限内要求真实布局和焦点后再取像素或注入输入，没有放宽断言或删去用例。

状态修正后的 API 34 / host GPU + skiagl 完整定向检查通过 31 项，零失败、零错误、零跳过。它包含新增五项真实窗口检查，以及既有 `PageGestureOwnershipTest`、`HeldRowOverflowPortalTest`、`HeldRowClipBoundsTest`、`PanelInlineScrollTest` 的完整用例，覆盖生产 Sample 的双向分页、纵向滚动、开关拖动、接住回弹、四向外溢、真实材质/高光、隐藏内容和退出恢复。最终库源码与候选副本逐项核对；副本独立包名不作为正式发布 APK 的字节身份。

## 发布验收边界

本地候选副本仅覆盖本次源码并替换独立 applicationId，基线、补丁和源码哈希另有记录，不将基线 SHA 声称为包含未提交修改的发布提交。模拟器和定向用例不外推其他厂商、长期性能或功耗。

发布前必须由精确 main 提交通过 CI 与 API 27/31/33/34 全量 Demo 检查，再创建不可变 1.5.3 标签。标签下 Demo 仍使用同一对 APK 完成四版本全量测试后上传。正式名称为 `LumenCoacervationEngine 1.5.3`；九模块公开 JitPack 身份、精确提交和全部附件摘要由最终发布脚本核验。远端状态以 `VERIFICATION_1.5.3.json` 和 `SHA256SUMS.txt` 为准，本文不预先宣称发布完成。
