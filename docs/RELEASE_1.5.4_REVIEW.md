# 1.5.4 优化与兼容复核

本轮以 70930f4 为固定基线；该基线已经包含展开手风琴下拖、页面裁剪和回抓修复。报告是候选分析资料，实施决定以实际源码、兼容性与测量为准。没有新增生产依赖、修改默认视觉质量或降低门禁。

## 采用项与逐步 review

1. 工作量快照与可重放负载：逐 owner 的被动 Long 计数，显式查询才分配；不记录 View、用户内容、URI 或来源路径。既有诊断 data class 不增加参数，保留构造及 copy 的二进制签名。
2. Effect 配置缓存：grain 仅依赖归一化 seed；film gradient 依赖完整 LumenFilmOptions 与颜色。所有五个 film 字段、颜色、正负 seed 和 0/1 边界经过测试。粒子仍按原始 seed 的变化 reseed，bounds 矩阵、裁剪与主动失效保持；初始化不再配置两遍。
3. Liquid 刷新率：ACTIVE / IDLE / PROBING 将采样与高 Hz 所有权分开。进入 idle 归还仍由自己持有的属性，探测不重新申请；热状态仍更新采样预算与周期，真实唤醒使用最新热/吞吐上限。首次候选在设备上暴露“归还属性触发 OnDraw → 重新申请”的循环，原始失败保留，修复后属性归还触发的首个绘制先确认像素，真实触摸可立即唤醒。系统未因属性归还而绘制时，首次成功的不变探测也会清除旧标记，避免随后真实绘制被错误归类。真实绘制打断在途探测时使票据过期，但缓冲单飞占用直到回调归还。
4. 位移窗口范围：可选 View 重载沿 delegate/session/GlowEngine 转发；默认实现调用旧无参方法。Liquid 只对已知窗口入队，未知与脱离窗口的 View 全窗口保底。内置 Activity/Dialog 弹性回调保留原 View。没有脏矩形裁剪、MOVE 延迟或子树范围假设。

## 实测与边界

API34、同一模拟器及相同工作负载的三轮结果：1000 次相同 Effect 更新，基线每轮新增 1000 次 grain/gradient 重建，优化后新增 0 次；配置循环耗时中位数 13.39ms → 2.85ms。纸纹哈希 -1121757768、薄膜哈希 1680062659 在全部基线/候选轮次一致。该数字只描述此配置循环，不能换算为整页帧率或功耗。

主窗口与弹窗共存时，100 次弹窗位移通知的窗口队列访问从 200 减到 100；单窗口场景不声称有该比例收益。静态实时场景保留每秒兜底探测，探测期间不重复配置、归还或写窗口刷新率属性；“归还偏好”不等于物理面板一定降 Hz。外部所有者修改的窗口字段、onStop/onStart 与分配失败回归单独验证。

最终候选在 420 dpi 的三轮 60 秒静止测量均通过：每轮 58–59 次兜底探测，刷新率 configure / restore 调用和窗口属性写入增量全部为 0。计数反映保留探测且没有刷新率申请抖动，不代表物理刷新率、GPU 时间或功耗。

## 暂缓项

| 报告候选 | 决定与依据 |
|---|---|
| ON_DRAW_ONLY / 默认 PixelCopy 退避 | 不改变默认；RT-only 变化不保证触发 Java OnDraw，继续每秒兜底 |
| PowerSave 监视集中化 | 暂缓；未取得本轮热点收益证据，避免新增进程级监听生命周期风险 |
| uniform 精确缓存 | 暂缓；尚无其为瓶颈的测量证据，保持每帧真实参数提交 |
| API31 同实例等价别名复用 | 暂缓；保持原 effect/alias 交替刷新修复，不增加缓存或几何量化 |
| Sensor 批处理 | 暂缓；会改变时延，缺少相应设备收益与时延测量 |
| 资产默认帧率或 Prism 默认色散下降 | 不采纳；会改变时序或画面，保持原默认值和分支 |

## 兼容与验收

- 与公开 1.5.3 的 core/motion/effects AAR 比较 11 个相关公开类的字段、方法、构造、默认桥接与泛型签名，无原成员删除或改变。另将自定义 GlowEngine 实现按旧 AAR 编译，再用候选接口执行新默认重载，旧无参回调恰好调用一次；此为 JVM 链接验证，使用非空 View 占位，不代替 Android 运行测试。
- 展开手风琴、隐藏内容、页面裁剪、原生滚动/CANCEL、回抓、负向边界和嵌套展开原实现保持；API31 滤镜交替、PixelCopy 单飞/三缓冲/遮罩时间点、反馈抑制、热与吞吐降档保持。
- 分步 API34 验证已通过 26 项联合回归。本地完整门禁包含 1035 个 JVM/源码契约测试、156 suites（含最终标记过期边界），无失败/错误/跳过；Debug、Sample release 单测、十模块 Lint、九模块 AAR/source、Sample R8、七组许可证归档检查及 53 个主机脚本测试通过。DEX 检查的高版本平台类型均处于既有 ApiNN 隔离类或其受版本门控加载的生成回调中。
- 源码/JVM、模拟器、OEM 真机、功耗和公开可用性分别判断；当前模拟器测量不声称 OEM 等价或功耗改善。四版本远端全量测试及公开产物结果由下述发布验证记录约束。
- Windows host GPU 的额外全量尝试不能作为通过证据：420 dpi 下阴影连续性、融合光晕与两项动效状态断言，在未优化的 70930f4 冻结包与候选包上同样失败；其余焦点/超时问题另作基础设施取证。320×640、160 dpi、4GB 的新实例实际出现 `com.android.systemui` ANR，系统对话框占据焦点，已保留截图、窗口与原始结果并停止该轮。没有放宽像素阈值、跳过原必测或改动相关生产策略。远端四版本使用既有标准配置与图形后端，全部原始断言必须通过后才允许发布；本轮不声称已解决这些高密度基线问题或所有 Windows 模拟器差异。
- 发布使用不可变同名标签、精确源码 CI/Demo、四版本必测矩阵、发布附件哈希及匿名 JitPack 核验；发布流水线生成的 VERIFICATION 与 SHA256SUMS 是远端结果记录。

公开 API 的新增属于本次明确指定 1.5.4 的编号例外；CONTRACT_VERSION=1、minSdk=27、存储名、schema 与既有默认选项保持。
